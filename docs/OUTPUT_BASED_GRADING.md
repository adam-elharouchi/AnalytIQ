# Output-Based Exercise Grading

Implemented on branch `staging-output-grading`.  
Replaces the previous Levenshtein / string-similarity grading system entirely.

---

## What Changed and Why

| Before | After |
|---|---|
| Grading ran in the browser (JavaScript) | Grading runs on the server in a sandboxed subprocess |
| Score = 70% string similarity + 30% time bonus | Score = 80% correctness (test cases) + 20% code quality |
| Student who copied structure scored highest | Student who produces correct output scores highest |
| Speed bonus incentivised copy-paste | No time component in score |

---

## Grading Schema (0 – 100)

### Correctness (0 – 80 pts)
- Each exercise has **5–8 test cases** generated by Gemini at creation time.
- On submission the student's code is run against every test case in a sandbox.
- `correctness_score = (weighted_tests_passed / total_weight) × 80`
- Edge cases carry weight 2; basic cases weight 1.

### Code Quality (0 – 20 pts)

| Check | Points |
|---|---|
| Code runs without compile/runtime error | 10 |
| No hardcoded answers (bare literal returns) | 5 |
| Has at least one meaningful variable name (>1 char) | 5 |

## Sandbox Security Model

| Control | Detail |
|---|---|
| Process isolation | Student code runs in a child `subprocess`, never in the Flask process |
| Timeout | 5 seconds per test case; `subprocess.TimeoutExpired` kills the child |
| Python import block | `subprocess`, `socket`, `ssl`, `shutil`, `multiprocessing`, `threading`, `asyncio`, `ctypes`, `signal`, `mmap`, `pty`, `termios`, `fcntl` all raise `ImportError` |
| File write block | `open()` monkey-patched to deny `w/a/x` modes; `RLIMIT_FSIZE=0` on Linux |
| Memory cap | `RLIMIT_AS = 256 MB` on Linux |
| No child processes | `RLIMIT_NPROC = 0` on Linux |
| stdin closed | `subprocess.DEVNULL` — no interactive input |
| JavaScript | `node --disallow-code-generation-from-strings` |
| SQL | `sqlite3` in-process — no network, no host filesystem |
| R / Java | Timeout only (see note below) |

> **Note on R and Java:** `resource` limits are not available for these runtimes without OS-level sandboxing (Docker / seccomp). On Render (Linux), consider running the grading worker inside a restricted container if R or Java exercises are widely used.

---

## Supported Languages

| Language | Runner | Security level |
|---|---|---|
| Python | `subprocess` + harness | Full (resource limits + import block) |
| JavaScript | `node` subprocess | Medium (`--disallow-code-generation-from-strings`) |
| SQL | `sqlite3` in-process | High (inherently sandboxed) |
| R | `Rscript` subprocess | Timeout only |
| Java | `javac` + `java` subprocess | Timeout only |
| Others | — | Returns `runtime_missing` error |

## API Reference

### `POST /api/exercises/<exercise_id>/grade`

Grades a student submission. Requires authentication.

**Request body:**
```json
{ "code": "<student source code>" }
```
The language is read from the database — the client does not control which sandbox runner is used.

**Response:**
```json
{
  "total_score":       85,
  "correctness_score": 70,
  "quality_score":     15,
  "tests_passed":      5,
  "tests_total":       6,
  "has_test_cases":    true,
  "language":          "python",
  "results": [
    { "description": "basic case", "passed": true,  "actual": 5,    "expected": 5,  "weight": 1 },
    { "description": "edge case",  "passed": false, "actual": null, "expected": 0,  "weight": 2,
      "error": "Runtime error: division by zero" }
  ],
  "quality_details": {
    "total": 15,
    "runs_cleanly": 10,
    "no_hardcoded_answers": 5,
    "basic_style": 0
  }
}
```

When an exercise was generated before migration 007 (no test cases stored):
```json
{
  "has_test_cases": false,
  "total_score": 0,
  "message": "This exercise does not have test cases yet. Ask your professor to regenerate it."
}
```

## Exercise Generation Changes

The Gemini prompt (`python/exercise_generator.py`) now requires every exercise to:

1. **Define a named function** that accepts parameters, returns a value, and also prints it.
2. **Include 5–8 test cases** with `input`, `expected_output`, and `weight`.

### SQL exception
SQL exercises do not define functions. `solution_code` is the SELECT query; test case `input` contains `{"setup": "<DDL + INSERT>"}` and `expected_output` is a list of rows.

## Deployment Checklist

1. **Run migration 007** against the production database:
   ```bash
   python scripts/migrate_007_exercise_test_cases.py
   ```

2. **Redeploy** the application (the new `grade` endpoint and `code_runner` must be live).

3. **Notify professors**: existing exercises have no test cases. They need to regenerate each chapter (delete and re-upload the PDF, or click "Regenerate Exercises") to get test-case–backed grading. Until regenerated, the grade endpoint returns `has_test_cases: false` and score 0.

4. **Optional**: if R or Java grading is used in production, consider running the Celery/web worker inside a Docker container with restricted capabilities for defence-in-depth.

## Known Edge Cases

| Scenario | Behaviour |
|---|---|
| Student imports blocked module | `ImportError` caught per test, test marked failed |
| Student uses wrong function name | Falls back to first user-defined callable; if none found, all tests fail with `no_function` error |
| Student prints instead of returning | Printed output captured and compared as fallback |
| Infinite loop | Killed after 5 s timeout |
| Empty submission | Immediate 0, no subprocess spawned |
| Code > 50 KB | Rejected before subprocess, score 0 |
| Missing library (`import pandas`) | `ImportError` in subprocess, test marked failed |
| Exercise has no test cases (pre-migration) | Returns `has_test_cases: false`, score 0 |
| Unsupported language (e.g. Scala) | Returns `runtime_missing` error per test |
